# 04｜经营模型与最小验证包

## 1. 先决定算哪一种生意

模型是为了看清成立条件，不是为了造一个精确预测。先识别客户、付款者、收费单位、交付方式、主要变动成本和时间周期。

| 品类/模式 | 优先收入单位 | 关键经营指标 | 容易漏掉的成本 |
|---|---|---|---|
| 消费订阅 APP | 每个付费周期或每个新增付费用户 | 下载到付费、续费、退款、每用户贡献 | 平台费、免费用户服务、AI、客服 |
| B2B 软件或服务 | 每个客户合同及其周期 | 合格线索到成交、销售周期、续约与扩张 | 销售人员、试点、实施、客户成功 |
| 电商 | 每笔订单/每名客户 | 贡献毛利、复购、退货、库存周转 | 物流、退换货、损耗、支付、客服 |
| 广告内容产品 | 每活跃用户或有效广告展示 | 留存、展示、填充、净 eCPM | 内容供给、版权、分发、审核 |
| 撮合平台 | 每笔完成交易 | 抽佣、完成率、双边复购 | 双边获客、补贴、争议、履约 |
| 线下服务 | 每次服务或每小时有效产能 | 客单、复购、利用率 | 人工、场地、空置、耗材 |

D1—D6 不变，但指标必须随模式调整。例如不能用 APP 下载量评估 B2B 销售机会。

## 2. 模型输入纪律

每个输入记录：数值或范围、单位、周期、地区、人群、依据类型、来源/判断 ID、局限。

依据类型至少区分：`measured`、`external_reference`、`estimate`、`assumption`。

不要用“行业平均”作为没有方法和来源的参数名称。没有成本数据时，写“尚未实测；反算可承受成本”，而不是从另一个品类找一个好看的 CPI。

所有情景先冻结口径：例如“美国 iOS、下载后 35 天内首次付费、首年收入贡献”。换渠道、地域、窗口时重新计算，不能直接拼接。

## 3. 首购订阅示例模型

以下是一个明确简化的模型，用来反算经营条件，不适用于所有账务或退款规则。

定义：

- `P`：一次首购的含义明确的订阅价格；示例假定已排除应单列税费。
- `r`：按金额计的退款比例，不是简单的退款人数比例。
- `f`：平台/支付综合费率；是否适用、是否含固定费及退款处理须另行核验。
- `Vp`：每名初始付费用户在本收入周期的变动服务成本，不含已记入 `Vi` 的部分。
- `Vi`：每次新增安装对应的共同服务成本，按所有安装分摊；包括需要计入的免费阶段成本。
- `p`：同一渠道、地区及窗口下，安装到首次付费的概率。
- `CPI`：每次付费渠道安装成本。

简化假定：退款先冲减销售额，费率按退款后的销售额计；实际平台不返还某些费用时必须修改模型。

```text
每名初始付费用户的净收入 R = P × (1 − r) × (1 − f)
付费层基础贡献 B = R − Vp
付费渠道 CAC = CPI / p
分摊免费及共同成本后的贡献 = B − Vi / p
扣获客后每名初始付费用户贡献 = B − (Vi + CPI) / p
每次安装可承受的 CPI 上限 = p × B − Vi
给定 CPI 所需的最低转化率 = (CPI + Vi) / B，前提 B > 0
```

上述贡献尚未扣固定团队费用、研发和其他未列成本，不得称为净利润。负的 CPI 上限表示即使不付钱获客，当前服务成本结构也可能不成立。

若需要利润或固定成本缓冲，应在贡献要求中额外预留，不能把理论盈亏平衡当成可经营的目标。

### 纯假设例子

设 `P=39.99`、`r=5%`、`f=15%`、`Vp=5`、`Vi=0`、`CPI=1.50`，币种统一为 USD。以上都是演算假设，15% 不是对任何平台当前费率的事实断言。

则 `B≈27.29`。在 `p=3%` 时，CAC 为 50，扣获客后贡献约为 −22.71；在 `p=6%` 时，CAC 为 25，贡献约为 2.29。此模型下理论所需转化约为 5.50%，但仍没有覆盖固定成本或留出利润空间。

这不是证明某品类不好，而是说明**所需转化和可承受获客成本必须由同一套账推导**。改变价格、退款、服务成本、平台费或渠道，结论就可能改变。

运行：

```bash
python3 scripts/calculate_economics.py model assets/unit_economics.example.json
```

脚本对 `p=0` 返回“无付费，按付费用户计的成本不可定义”，不会除零或把 CAC 伪装为零。参数非有限值、超出比例范围或遗漏时会报错。

## 4. 留存、LTV 与现金回收

不要因为有订阅就默认用户会续费。首年预付现金不等于未来每年稳定收入；月活也不等于付费留存。

需要长期模型时，优先按同一批首购用户观察有限周期：

```text
H 期贡献价值 = Σ[t=1..H]（第 t 期仍付费概率 × 该期条件贡献）
```

若使用折现，再按明确折现率调整；没有数据的尾部不得无限延伸。`平均月收入 ÷ 流失率` 只有在严格稳态等假设下才可能作为近似，不能默认套用。

付费留存、使用留存、续费率各自有分母和事件，必须分开。年订阅尚未走完一年时，不能从两周使用情况声称已证明年续费。

自然流量不等于免费：内容、人力、合作分成和已有资产使用成本至少应列为成本或明确未分摊项。付费 CAC、混合 CAC 与全成本 CAC 不要混称。

## 5. 敏感性分析：从“预测成功”改为“什么条件下值得试”

至少查看以下变量中对结果最重要的两到三个：价格、付费转化、退款、获取成本、服务成本、复购/续费、供给利用率。

不要只做一个“基准”情景，再把它当成未来。展示保守/基准/较好条件，所有条件注明来源或假设；不能把“较好”情景称为高概率。

当结果只在极乐观参数组合下成立时，把它写进决策。多项看似合理的单独假设同时成立，并不意味着组合也合理。

同一批人中更高价格可能降低转化，扩大投放可能改变客群和成本。不可把相互影响的变量永远视为独立旋钮。

## 6. 最小验证包不是小型完整产品

验证包的目标是获得能改变决策的信息，不是证明团队能开发。

选择原则：**对决策重要、当前把握不足、通过有限投入可获得真实证据。**

优先验证一到三个假设，例如：

- 用户是否已经为问题付出明显代价，问题发生在哪个具体场景。
- 一个窄方案是否比免费或现有方案有足够增量价值。
- 用户是否会真实付费，获得价值后是否继续。
- 在一个明确定义的渠道中，触达和交付成本是否落在可承受范围内。

不应把“访谈觉得有兴趣”作为支付证据，也不能把“广告点击不错”当成留存或利润。

## 7. 三种验证层次

### 探索：找清问题与可行切口

使用目的性访谈、现有工作流程观察、人工服务或低保真原型。样本依据是问题和人群是否覆盖，不是要估计总体比例。可以从约 10—20 个符合条件的访谈起步，但这是可调整的工作安排，不是达到人数便可宣称饱和。

输出：明确场景、替代方案、失败原因、愿意付出的真实成本，以及下一轮可测试方案。

### 方向验证：观察真实行为

给符合条件的人一个真实可用的窄方案，在明确服务和退款规则下观察采用、付款和重复使用。小规模样本可以发现明显问题，但不能宣称精确转化率或已经完成产品市场匹配。

在对照测试中固定招募条件和主要任务。不要让两个版本同时改价格、渠道、产品和人群，以致无法解释差异。

### 经营验证：估计可重复的转化、成本和留存

预先定义主指标、基准、最小有意义差异、观察窗口、样本方案和预算。需要统计判断时进行功效/精度规划；不要在结果出来后改成功标准。

比例区间演示可用：

```bash
python3 scripts/calculate_economics.py wilson --successes 3 --total 100
```

该脚本计算二项比例的 Wilson 区间，默认 95% 置信水平。这是对特定独立二项观测模型的统计计算，**不能修复招募偏差、重复用户、选择性观察或渠道不代表性**。置信区间也不是本 Skill 对证据质量使用的“高/中/低置信度”。

若随时看结果并随时决定停止，应使用预先确定、适用于序贯测试的设计；不把反复窥看后的普通显著性结果当成原设计检验。

## 8. 指标必须有事件、分母、窗口和对照

| 目标 | 可考虑指标 | 需要排除的误读 |
|---|---|---|
| 付费价值 | 合格用户中实际付款比例、退款、购买理由 | 邮箱留资不算付费 |
| 采用价值 | 完成真实核心任务的用户比例 | 打开页面不算任务成功 |
| 持续价值 | 固定周期内重复完成共同任务、续购/续费 | 打卡次数多不一定创造价值 |
| 获客可行 | 同渠道的完整漏斗、成本与付费用户数 | 不能拼接不同渠道的最佳数字 |
| 交付可行 | 每用户服务时长、错误、投诉、变动成本 | 人工超额服务不能假定能规模化 |

在健康、金融或其他高风险场景中，成功指标不能鼓励有害行为；不要通过惩罚、隐瞒或夸大承诺换取留存。伦理和专业审核是验证设计的一部分。

## 9. 预算与继续/停止条件

预算按成本项目估算：招募、原型、专业审核、服务交付、渠道、退款准备和测量。已有团队薪资是否包含必须写清，不同外包方式不能用同一个预算承诺。

不把上次项目的价格、样本数和预算原样复制。预算止损线是投入管理建议，不是行业标准。

继续条件应来自模型或学习目标；停止条件包括无真实价值、单位经济无法改善、需求不适合当前能力、验证风险不可接受等。结果不确定时写“不确定，需要什么新增信息”，而不是硬把小样本判成成功或失败。

## 10. 最终决策写法

最终仍然只围绕“值不值得出最小验证包”，不变成直接批准长期项目。

- 值得：指出具体人群、场景、假设、预算边界和关键限制。
- 不值得：指出主要原因，以及什么新证据可能改变判断。
- 目前不足以支持投入：指出决定性缺口，必要时只建议更小的补证动作，不伪装成完整产品立项。

以上是同一决策的不同答案，不是新增三层框架。不要默认所有研究都应得到“值得验证”的结论。
